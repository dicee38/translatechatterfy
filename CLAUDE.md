# Chatterfy AI Translator — расширение для Chrome (Manifest V3)

Отдельное, самостоятельное расширение — **не часть** `Chat Summarizer`
(другой проект, другая зона ответственности и чувствительность
данных: там статистика по лидам, здесь — личная переписка с живыми
людьми).

Помогает оператору вести переписку на диалекте собеседника: перевод
по выделению текста, расшифровка+перевод голосовых, в перспективе —
подсказка ответа с подтверждением оператора перед отправкой.

**Полное ТЗ: `docs/TZ.md` — читай его перед началом любой задачи.**
Там термины, архитектура целиком, схема API `messages/v1/search`
(данные берутся из него, не из DOM — см. п.0.1), спецификация
бэкенда-прокси, все три фичи с UI-состояниями и формат манифеста.

## Архитектура (не менять без явной просьбы)

```
content script (v2.chatterfy.ai) → свой бэкенд-прокси → OpenAI (транскрипция, перевод, умный ответ)
```

- **Данные — из API, не из DOM.** `POST /api/messages/v1/search`
  (`{chat_id, limit}`) отдаёт всю историю чата: `content` (текст),
  `sender_type: "incoming"/"outcoming"` (собеседник/оператор),
  `files[]` с `type: "voice"`, прямым `url` на `.ogg` и
  `meta.duration` — этого достаточно и для контекста диалекта, и для
  списка голосовых. DOM парсится **только** для позиционирования
  кнопок/плашек рядом с нужным сообщением, не для самих данных.
- **Ключ API никогда не в расширении.** Content script стучится в
  свой бэкенд-прокси (Cloudflare Workers или VPS — см. `docs/TZ.md`
  п.3.5), прокси держит ключ OpenAI и вызывает его сам. Один вендор на
  всё (транскрипция, перевод, умный ответ) — один ключ, не два.
- **Прокси обязателен: авторизация + бюджетный лимит.** Без токена на
  запросах к прокси и без дневного/месячного лимита по стоимости —
  прямой риск слить весь баланс API. Оба пункта — не опция, часть
  MVP с первого этапа (см. `docs/TZ.md` п.3.2–3.3).
- **Прокси не хранит контент дольше самого запроса.** Это переписка
  с реальными людьми — логировать текст/расшифровки на бэкенде
  дольше, чем нужно для ответа, не надо (см. `docs/TZ.md` п.3.4, 8).
- Три фичи — **read-only помощь**, ничего не отправляется и не
  меняется в Chatterfy автоматически. У Feature 3 (умный ответ) это
  отдельно закреплено архитектурно: вставка предложенного текста в
  поле ввода — только по явному клику оператора «Вставить», без
  автоотправки, это не ограничение MVP, а постоянное решение.
- **Поле ввода сообщения — Quill (`contenteditable`), не
  `<input>`/`<textarea>`.** Для Feature 3 вставка текста — через
  `document.execCommand('insertText', ...)`, не через React-инпут
  трюки (см. `docs/TZ.md` п.6.2).
- `manifest.json` — узкий `host_permissions` (конкретные домены
  Chatterfy + свой прокси), не `<all_urls>` как у Chat Summarizer —
  этому расширению не нужен доступ ко всему интернету.

## Чек-лист по этапам (docs/TZ.md, раздел 9)

- [ ] **Этап 1.** Ручная проверка качества STT (`gpt-transcribe`) на
      10-15 реальных голосовых нужного диалекта — не код, до старта
      Feature 2. Если результат систематически плохой — Feature 2
      нужно пересогласовать, а не писать как задумано.
- [x] **Этап 2 (скелет для обоих вариантов деплоя, сам деплой не сделан).**
      Бэкенд-прокси в двух версиях с одинаковым контрактом
      `/translate`/`/transcribe`, авторизация по токену, бюджетный
      лимит ($5/день по умолчанию, 429 при превышении). Один вендор на
      всё (транскрипция, перевод, умный ответ) — один ключ
      OPENAI_API_KEY, Claude/Anthropic не используется.
      - `proxy/` — обычный Node/Express, под VPS. Curl-проверен,
        покрыт `npm run test:skeleton` (MOCK_MODE=true).
      - `proxy/workers/` — под Cloudflare Workers (бесплатный тариф),
        KV вместо файла для счётчика, нативный `request.formData()`
        вместо `multer`. Проверен и логическим тестом
        (`npm run test:skeleton`, фейковый KV), и вживую через
        `wrangler dev` на настоящем Workers-рантайме (Miniflare) —
        `/health`, `/translate`, `/transcribe`, авторизация и рост
        бюджетного счётчика отработали.
      - Ни то, ни другое реально не задеплоено (нет аккаунта
        Cloudflare/VPS, подключённого в этой сессии) — команды для
        деплоя описаны в `docs/TZ.md` п.3.5.
- [x] **Этап 3 (без реального /translate).** Feature 1 целиком —
      content script (`extension/`): выделение текста, плашка с 4
      UI-состояниями, контекст диалекта через `messages/v1/search`,
      кэш. Вся цепочка content script → background → локальный прокси
      в MOCK_MODE проверена end-to-end. DOM-селекторы чата и точная
      форма ответа `messages/v1/search` — не подтверждены на живой
      странице v2.chatterfy.ai (не было доступа в этой сессии),
      отмечены TODO в `extension/content.js`.
- [ ] **Этап 4.** Feature 2 целиком — список голосовых через API
      (`files[].type === "voice"`), `/transcribe`, прогон через тот же
      `/translate`, персистентный кэш по `chatId+messageId`,
      UI-состояния (+ «распознавание не дало разборчивого текста»).
- [x] **Этап 5.** Полировка — попап (`extension/popup.html`,
      `popup.js`): вкл/выкл Feature 1, ручной override диалекта
      (`targetLang` в `/translate`), настройка адреса прокси/токена
      (`chrome.storage.local`, общие дефолты в
      `extension/shared-defaults.js`), индикатор дневного бюджета
      через `GET /health`. Feature 2/3 переключателей нет — самих
      фич ещё нет, добавлять на их собственных этапах. Не требовало
      ключей моделей, проверено логикой против локального
      MOCK_MODE-прокси (`/health` отдаёт форму, которую ждёт
      `popup.js`); визуально в браузере не открывал — нет браузера в
      этой сессии.
- [ ] **Этап 6 (перспектива).** Feature 3 — контекст диалога,
      генерация ответ+обратный перевод, вставка в Quill-поле через
      `execCommand`, тест-кейс на отсутствие случайной автоотправки.

## Как работать

Ссылайтесь на конкретный этап в промпте, например:

```
Реализуй этап 2 из docs/TZ.md: скелет бэкенда-прокси с /translate и /transcribe
```

Claude Code сам откроет `docs/TZ.md`, найдёт нужный раздел (архитектуру,
формат эндпоинтов, промпты) и будет держать в контексте правила из
этого файла на протяжении всей сессии.
